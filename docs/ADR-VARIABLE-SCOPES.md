# 变量作用域与持久化契约（实现前决策）

状态：本地实现与契约测试已通过，待此提交的完整 CI。本文记录实现前确定的契约；通过本地测试不等于全部交付。

## 范围与公开依据
- 当前请求临时变量：预脚本→请求插值→后脚本有效，下一请求不可见。
- 环境变量：绑定所选环境，修改持续到再次变更。
- 全局变量：项目内跨环境共享。
- 依据：https://wiki.apipost.cn/docs/http/temp-variables/ 、https://wiki.apipost.cn/docs/http/environment-variables/ 。它们是在线版补充说明，原版单机完整 SDK 的其他行为不因此得到证明。

## 明确契约
1. 解析优先级：请求局部 > 既有工作流/调试运行变量 > 环境 > 项目全局。
2. pm.variables 只读写请求局部。apt.setVar 保留当前工作流/调试变量的兼容行为。
3. pm.environment、apt.environment、apt.variables 操作所选环境；pm.globals、apt.globals 操作项目全局。scope get 只读取该层，不能悄悄读取别层。
4. 每个脚本调用以事务方式返回作用域修改；脚本异常/VM 超时不提交半成品。
5. 前脚本环境/全局变更成功落盘后再发送请求。网络失败不会撤销已完成的前脚本写入。后置提取和脚本的持久化变更作为一个阶段提交。
6. 提取目的层明确可选：运行变量（默认兼容现有计划）、请求局部、环境、全局；非法层拒绝。
7. 持久化使用字段级旧值比较：允许并发修改其他字段，不覆盖同名变量的外部修改；沿用 Store 的版本/文件指纹检查。版本竞争可重新读取后有界重试，同名变量冲突必须报错。
8. 持久化失败保留实际请求/响应证据，步骤失败；恢复该阶段未提交的环境/全局内存层。不能把变量未保存伪装成执行成功。
9. 本地项目文件与已有调试缓存需保持一致。UI、HTTP/stdio MCP、CLI 都使用同一执行规则；权限不足的 MCP 不会获得写入/执行工具。
10. 默认值、false、0、空字符串和 null 必须保留。禁止原型污染变量名；作用域操作不能新增网络/文件/进程脚本 API。

## 固定验收（先明确，后实现）
- 同名四层优先级与跨请求局部销毁；同环境共享、跨环境隔离、全局跨环境共享。
- 设置/删除/清空作用域，删除环境值后露出全局值；运行层遮蔽仍生效。
- 正常重启能读到已保存环境/全局变更。
- 前脚本抛错/超时无持久化；网络失败后前脚本已提交的值仍在。
- 同名并发修改报错且不覆盖；无关并发修改保留。
- 提取的四种目的层在后脚本和下一步可见性符合契约。
- UI、MCP、CLI 至少一个真实请求链路覆盖各共享执行路径；测试只使用本地固定 fixture。
