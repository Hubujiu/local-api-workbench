# Bounded canonical plan failure policy

This independent feature depends on fixed PR91 head b839507e7bdf9aa93f6eae1b2be919126eed256f (tree 03538bfd9f400ae037d9e6a144467cb217322906), containing the existing PR44 repeat and PR88 admission dependencies. It does not add the whole integration tree or modify PR91.

Legally obtained official Offline2 2.0.0 static runner evidence establishes an optional failure-stop control: send/index.js SHA256 5dabd6d0b85214084895a7044f9b045bb005cb010ecec156e98cf883a914ceff, decoded-text region 33638350–33640800. Its ordered dispatcher checks ignore_error after assertion/request failure and only recurses to later events when permitted. No original code is copied or executed. Saved event_list/settings assembly remains unproved, and this canonical option is not a native saved-format adapter.

Proposed contract: omitted failurePolicy and explicit "continue" retain existing semantics and exact old snapshot bytes (continue is normalized to omission). "stop" retains the completed failed leaf, then stops the entire plan before any later leaf, repeat iteration or IF group. A correctly expected error response remains passed. Ordinary script/assertion/transport failures use the final existing leaf status. This option does not roll back prior network/database effects or confirmed variable commits, and never retries. No new dependency, runtime budget or credential permission is introduced.

Existing cancellation, full-definition credential preflight, native strict extraction, terminal/progress failures, protocol script unknown scope commit and evidence limits remain mandatory. Continue cannot override those stops. Stop evidence uses stopReason "step-failure" plus bounded failureStop leaf/repeat identity, with no fabricated skipped/passed results. All earlier actual evidence is persisted by existing receipts, including uncertain-save recovery without replay. Cancellation remains execution status priority; pre-existing more specific stop reasons are not replaced.

Freeze/version/provenance/hash, owner saves, CLI, MCP, history/chunk reads and backup/restart must retain the option. Omitted update preserves an existing stop option; explicit continue clears it. Native definition/result projections must reject the unrepresentable policy rather than silently erase it. Old policies/hashes and old imported history must not be rewritten.

Initial real HTTP tests are intentionally RED and do not establish acceptance. Required workflows include owner/CLI/official MCP, isolation, nested repeat/IF, disabled nodes, expected errors, pre/post script failures, cancellation, no downstream effects, unchanged default, complete stored/reopened evidence and genuine unknown journal recovery. Source audit uses a real loopback peer and runPlan's public injected executor; that audit is not owner/CLI/MCP acceptance. Exact-head CI and later root composition are separate requirements.
