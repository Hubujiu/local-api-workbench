# Bounded NTLMv2 handshake MIC compatibility

## Frozen contract and status

This feature extends the existing explicit-credential NTLMv2 HTTP/1.1 client. It is a standards-based compatibility improvement, not proof of original Apipost MIC equivalence, integrated Windows authentication, or complete NTLM interoperability. Apipost's public request-authentication documentation lists NTLM Authentication [Beta], without a MIC-specific contract: https://v7-wiki.apipost.cn/docs/11/ .

The feature starts at exact develop commit `88f70bb515c48b93536b28b7fe3ec780f2e150f3`, tree `107767d4d92f69fc0b5a048d41371267fea5a568`. No dependency branch, new package, new cryptographic algorithm, saved setting, frontend change, engine change or safety-budget change is required. This initial contract commit is **not implemented or accepted**; subsequent stages and actual CI must establish the workflow.

## Wire contract

- Use MS-NLMP connection-oriented client processing, section 3.1.5.1.2: https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-nlmp/c0250a97-2940-40c7-82fb-20d208c71e96 . This is not the connectionless two-message MIC procedure.
- For an accepted Type2 containing `MsvAvTimestamp`, provide MIC. Also preserve an accepted `MsvAvFlags` value containing only bit `0x2` by providing MIC. `0x2` **indicates that the client supplies MIC**; it is not a generic server-requires-MIC switch. Only values `0` and `2` are admitted; other bits remain unsupported. AV duplicates, malformed lengths, unknown/unsupported AV identifiers, and existing size caps remain rejected.
- Before computing the NT response, copy the original TargetInfo and set/add one `MsvAvFlags=2` before its end marker. Do not mutate the received challenge. Keep the exact bounded raw Type2 bytes, including original AV ordering/padding, for the transcript. Do not reconstruct the transcript from selected fields.
- Use the exact Type1 bytes actually sent by this HTTP exchange. Compute the SessionBaseKey from the existing ResponseKeyNT and NTProofStr using Node's HMAC-MD5; with key exchange/sign/seal still forbidden this is the exported session key. Compute MIC over exact Type1 + exact Type2 + the final Type3 with its 16-byte MIC zeroed, then fill that field. No zero, guessed, or regenerated Type1 transcript is accepted for a MIC exchange.
- MIC Type3 has the 8-byte Version slot followed by 16-byte MIC, and payload offsets start at 88. When the negotiated version bit is absent, the Version slot is all zero. The official structure specifies this zero slot: https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-nlmp/033d32cc-88f9-4483-9bf2-b273055038ce .
- A challenge without timestamp and without MIC indication retains the existing no-MIC layout and response behavior (including absent-version payload offset 64). Saved auth schema, frozen request definitions/hashes and historical records do not gain transcript or key fields. Temporary response/session keys are not returned or persisted by the new path.
- AV meaning and response-key derivation follow https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-nlmp/83f5e789-660d-4781-8491-5f8c6641f75e and https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-nlmp/5e550938-91d4-459f-b67d-75d70009e3f3 . No proprietary implementation is copied.

## Unchanged safety and format boundaries

Continue to refuse EPA/channel binding, target SPN/SingleHost, NTLMv1/LM downgrade, session signing/sealing/key exchange, proxy and HTTP/2 modes. Only explicit fictional/user-provided credentials are used: no OS identity, credential store, password hashes or real-account authorization discovery. Preserve TLS verification/custom CA/client certificate behavior, one isolated same socket, response limits, total deadline and cancellation. A challenge exchange still has at most the existing Type1 request and one authenticated Type3 request; never retry a failed MIC using weaker authentication, follow redirects with credentials, or replay on a replacement socket. This does not promise that a POST body appears only once across the two existing handshake rounds.

Keep the existing explicit NTLM cURL refusal and native-format boundaries. Workbench request/project backup must preserve the same saved auth definition; no new native private field is inferred. This feature does not add root-only typed persistence receipts to the develop-based branch. Root integration must retain its newer Cookie/cancellation and uncertain-commit handling.
