# Exact Query, Header and text-form function templates

Static inspection of the official offline 2.0.0 send adapter shows `$function.fn_name(raw text)` passing the captured text as one argument, with case-insensitive registry lookup. Quotes and commas are not parsed as JavaScript or JSON arguments. Template-level synchronous exceptions preserve the original expression, unlike the direct-script wrapper that returns its input text.

The supported import subset is an exact `{{$function.fn_name(text)}}` in an enabled API Query, Header or text-form value. Embedded expressions, nested parentheses/braces, pipelines, other parameter locations and source function references absent from the incoming library reject atomically. Inherited parameter copies into converted samples retain the same explicit dynamic definition. No function runs during import.

The internal dynamic sources are `apipost-function` for Query and `apipost-header-function` for Header and `apipost-form-function` for urlencoded/form-data text. Source and parameter position must match. It requires exactly one matching imported function and permits no extra processing chain. The sandbox calls the body synchronously, without the direct-script fallback wrapper or implicit await. Template evaluation reduces timer, microtask and network-request allowances to zero, preventing detached asynchronous changes to the captured result. Only finite primitive JSON results are supported; object, undefined, Promise, excessive output and VM-budget failure remain errors. The existing VM authority restrictions remain in place; source functions cannot obtain arbitrary host modules. Syntax and unsupported dependencies are not promised to match the original host runtime.

Requests using these sources are limited to Query/Header/form text, without SDK URL mode, pre/post scripts or operations, unrelated dynamic sources or dynamic bodies. Validation runs before plan operations and is repeated during resolution. Existing limits are not enlarged: at most 20 function transformations, the existing aggregate 5-second deadline, and the current VM activity, memory, code and output budgets. Results are inserted after ordinary interpolation and cannot be interpreted a second time. Disabled values do not execute.

Both request and snapshot editors preserve the explicit source and expression and explain the distinction. Preview is an explicit user action, not evidence of the next request's random or external state. Project backups retain definitions and function libraries. cURL and OpenAPI exports reject active templates instead of exporting empty values as equivalent requests.

Fixtures are independently authored. Tests cover raw quoted/comma input, case lookup, template-specific exception fallback, rejected async/nonprimitive results, limits, authority boundaries, atomic import, actual HTTP literal output, normalized/snapshotted definitions, editor preservation and browser import/edit/save/reload/send. This does not establish original GUI parity, full function pipelines, arbitrary native directory compatibility or original-runtime equivalence for untested values.

The original beforeRequest adapter substitutes expression results into a URL string before rebuilding its SDK URL. This is not proven equivalent to encoding every function result as one local Query value. Query outputs containing URL structural/escape characters (`& # + % ? =`, CR/LF) or replacement-dollar syntax therefore reject; an unchanged original-template fallback does not count as new dollar substitution. Empty results with query_add_equal disabled also reject because the original placeholder initially emitted an equals sign. These are explicit interoperability limits, not claims of full URL-wire parity.

Header templates share the same isolated synchronous evaluation and overall transformation budget but do not apply Query URL escaping restrictions. Header text such as Base64 padding, plus, percent, ampersand and fragment characters remains literal. CR/LF and ambiguous replacement-dollar results still reject before HTTP; ordinary header/transport validation is unchanged. Static evidence is the original beforeRequest header-member substitution loop. Browser fixtures verify both modes together through preview, editing, persistence and a server echo, not merely a locally displayed request object. Header names, raw body templates, files, processing chains, original GUI equivalence and untested signing interactions are not claimed.

Text forms follow the original beforeRequest urlencoded/formdata member-value substitution loop, not Query URL-string substitution. URL punctuation and embedded line breaks remain ordinary form data; urlencoded encoding and multipart framing stay in the existing transport. Replacement-dollar ambiguity still rejects. The form-specific source is valid only in text form rows with a matching urlencoded/form-data body mode; file template inputs are rejected before conversion so their original values cannot disappear when file metadata is normalized. Raw body, field-name and inherited global/folder expression templates remain unsupported. Query, Header and form transformations share the same 20-call / 5-second ceiling and zero async/network budgets. Fixtures verify both form transports over actual HTTP, literal marker preservation, edit/reload persistence and file/unsupported-mode refusal.

Native multipart file declarations use `field_type: File`, not only the legacy `type: file`. They are normalized to explicit file-reselection metadata without reading source paths. Embedded file payloads, unsupported per-part Content-Type and inherited files are rejected rather than flattened into text or silently discarded. A file value containing a function expression is not eligible for text-template conversion.
