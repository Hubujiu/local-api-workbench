# Exact Query function templates, not the full original expression engine

Static inspection of the official offline 2.0.0 send adapter shows `$function.fn_name(raw text)` passing the captured text as one argument, with case-insensitive registry lookup. Quotes and commas are not parsed as JavaScript or JSON arguments. Template-level synchronous exceptions preserve the original expression, unlike the direct-script wrapper that returns its input text.

The supported import subset is an exact `{{$function.fn_name(text)}}` in an enabled API Query value. Embedded expressions, nested parentheses/braces, pipelines, other parameter locations and source function references absent from the incoming library reject atomically. Inherited Query copies into converted samples retain the same explicit dynamic definition. No function runs during import.

The internal dynamic source is `apipost-function`. It requires exactly one matching imported function and permits no extra processing chain. The sandbox calls the body synchronously, without the direct-script fallback wrapper or implicit await. Template evaluation reduces timer, microtask and network-request allowances to zero, preventing detached asynchronous changes to the captured result. Only finite primitive JSON results are supported; object, undefined, Promise, excessive output and VM-budget failure remain errors. The existing VM authority restrictions remain in place; source functions cannot obtain arbitrary host modules. Syntax and unsupported dependencies are not promised to match the original host runtime.

Requests using this source are limited to Query text, without SDK URL mode, pre/post scripts or operations, other dynamic sources or dynamic bodies. Validation runs before plan operations and is repeated during resolution. Existing limits are not enlarged: at most 20 function transformations, the existing aggregate 5-second deadline, and the current VM activity, memory, code and output budgets. Results are inserted after ordinary interpolation and cannot be interpreted a second time. Disabled values do not execute.

Both request and snapshot editors preserve the explicit source and expression and explain the distinction. Preview is an explicit user action, not evidence of the next request's random or external state. Project backups retain definitions and function libraries. cURL and OpenAPI exports reject active templates instead of exporting empty values as equivalent requests.

Fixtures are independently authored. Tests cover raw quoted/comma input, case lookup, template-specific exception fallback, rejected async/nonprimitive results, limits, authority boundaries, atomic import, actual HTTP literal output, normalized/snapshotted definitions, editor preservation and browser import/edit/save/reload/send. This does not establish original GUI parity, full function pipelines, arbitrary native directory compatibility or original-runtime equivalence for untested values.
