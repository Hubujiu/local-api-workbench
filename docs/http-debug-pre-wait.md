# 普通 HTTP 手动调试：前置等待

项目定义保存的前置等待为
`{ "type": "wait", "waitVersion": 1, "milliseconds": 1000, "enabled": true }`。
时长是 0 至 10000 的整数（毫秒）；同一请求已启用的等待合计最多
10000 毫秒。关闭不删除时长，也不延迟执行。此上限是 Workbench 的限制，
不代表 Apipost 的上限。

只在普通 HTTP 手动调试的明确发送中执行。等待按前置操作列表顺序运行，
在前置脚本及主请求发送之前完成。列表在任何操作开始前进行结构验证。
含已启用等待的请求使用所配置的请求超时作为额外的前置阶段时限；
传输自身的超时规则不变。取消或超时停止尚未开始的后续工作，不撤销先前已完成
的操作，也不自动重试。记录的等待表示本地前置操作完成，不表示远端收到请求。

旧未标记的等待、普通后置等待，以及与 GraphQL、SDK URL 或原版任务模型混用
均不支持。新版普通前置等待也不能与原版动态函数模板混用。普通动态处理
在每个动态值或加工函数之间检查取消和时限。旧未标记行可以查看和备份，
不会自动升级。
用例、冻结计划、负载执行、直接传输和不能无损表示等待的导出不会默默略过等待。
请在普通 HTTP 调试中执行，或使用 Workbench 项目备份保留定义。
