# Inline data rows in canonical repeat plans

A canonical `repeat` group may optionally include `rows`, with exactly `count` inline JSON objects. For each group iteration the existing script context exposes that row via read-only `pm.iterationData` / `apt.iterationData` and exposes its zero-based index and total through the existing `pm.info` / `apt.info` iteration fields. The row context applies to every descendant request/script occurrence within that iteration and the prior outer execution context is restored automatically after leaving the group. A nested fixed repeat or condition may run inside a data-row repeat; a data-row repeat inside another data-row repeat is rejected. This does not directly add row keys to interpolation variables or make them available to IF operands: a script may explicitly publish a value using the existing scoped variable APIs when needed. Rows do not grant file, URL, database, write or protocol authority.

Rows are frozen into the saved plan and its full execution snapshot; do not place secrets in them unless that persistence is intended. Existing per-step progress and occurrence identity contain only stable IDs/indices, not row values. Existing fixed-repeat occurrence IDs and snapshots remain unchanged. Inputs must be strict JSON objects, 1–100 rows matching count, at most 50 top-level fields and 512 KiB per row. Nested arrays must be dense and have no extra properties, data must have no accessors, invalid numbers or unsafe keys, and existing graph depth/node/occurrence limits remain. For logical expansion accounting, the largest row bytes are conservatively charged for each potentially expanded descendant request, including disabled and conditional branches. The 4 MiB expanded-configuration limit remains in force.

This bounded canonical capability is based on observed original data-loop functionality; it is not a claim that native `automated_testings` data or source-driven/condition-until loops can be imported or reproduced. Existing owner, SDK, CLI, snapshot, cancellation and receipt rules remain authoritative. Inner data rows temporarily replace the outer script iteration context; outside the group the outer context is restored. No rows are loaded from external files or services by this feature.
