# Bounded modern sample-group import

The offline 2.0.0 static work mapper (module 526737, sample mapper) emits `sample_group` records separately from complete HTTP samples. Group records carry identity, API ownership, hierarchy, name and sort; they do not carry an executable request. Groups with unexpected content or nonempty method/URL fields are rejected rather than losing content. Stable project-namespaced group IDs are mapped to the local case-folder model, including empty groups. All parents must be groups owned by the same API; dangling, cyclic, deep, duplicate or conflicting IDs fail before project mutation.

The static send adapter (module 842216) treats root and grouped samples differently: it obtains the sample parent and begins ancestor traversal at that parent's parent. Root samples therefore exclude the source API's own request layer; samples below a group include it. The converter explicitly inserts the API request layer only for grouped samples. Existing project/folder/API/sample lexical ordering and inert provenance remain intact. It does not turn groups into API folders or pollute the ordinary request list.

Inherited body parameter rows remain outside the currently supported converter and cause rejection. The source API's raw body is not an inherited parameter: it remains on the ordinary API, while the grouped sample retains its own body. Project/folder inherited raw bodies remain unsupported. Automatic test trees, arbitrary database/wait/assert tasks and full original runtime semantics remain unsupported. These are import-time execution snapshots; moving a local group or editing a source API later does not recalculate an existing case. This is a static-source-informed bounded conversion, not evidence of original GUI execution parity.

All derived case folders and cases are validated together with their new API IDs before committing the import. Reimport conflicts cannot append partial APIs. Native project backups retain folder ownership and cases. Tests compare root versus grouped real HTTP headers, query and script results, preserve empty child groups, reject unsupported graphs atomically, and exercise HTTP restart/restore plus visible browser import and explicit execution under a selected environment.
