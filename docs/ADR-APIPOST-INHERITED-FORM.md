# Modern inherited form-text parameters

For HTTP APIs and samples with an explicit `urlencoded` or `form-data` body, the modern converter now merges ancestor body parameter rows using the same bounded scope rules as other parameters. Closest enabled rows override ancestor name groups; disabled child rows do not hide enabled defaults, and inherited system rows remain effective. The request's body mode is never changed. Project, folder and grouped-source API layers are import-time snapshots, not live linked settings.

This closes a formerly explicit rejection, rather than adding arbitrary source execution. The legacy form normalizer and HTTP runtime retain all existing value, size, file-selection and network limits. Inherited file fields or unknown non-text kinds still reject; no source file path is read. Non-form requests with ancestor form parameters remain rejected until their source behavior and retention can be represented explicitly. Unsupported project/folder raw-body inheritance still rejects. Empty projects or folders with unapplied form defaults reject rather than silently dropping those resources.

Independent HTTP fixtures cover urlencoded decoding, multipart body bytes, scope override, disabled rows, system flags and unchanged input. Negative tests verify atomic rejection for files, empty-resource loss and mismatched body modes. Browser coverage imports a folder-scoped form request, sends it under a selected environment, and verifies the server-decoded body fields. Original static send adapter module 842216 supplies the body.parameter inheritance boundary; this is not a claim that the original application was run.
