# Explicit-credential NTLMv2 HTTP compatibility

Design before implementation: provide a bounded NTLMv2-only HTTP/1.1 flow on one isolated keep-alive connection. Explicit username/password/domain/workstation only; never read OS identity, credential caches, hashes or tokens. No NTLMv1/LM fallback. Reject HTTP/2/proxy mode initially instead of changing transports silently. Retain normal TLS validation, custom CA/client certificate support, existing response caps and one total deadline; never follow redirects or retry credentials on another origin or replacement socket.

Parse challenge buffers and AV pairs with strict length/capability checks. Client challenge comes from crypto.randomBytes. Legacy MD4 is used only as specified by NTLMv2, never for application password storage. Server-required MIC/EPA/channel binding/session signing/sealing are explicitly unsupported and must fail, not be disabled or silently stripped. This is limited legacy-service compatibility, not a claim to support all NTLM deployments or modern integrated Windows authentication.

Implementation reference: Microsoft MS-NLMP sections3.3.2 and4.2.4. The fixed User/Domain/Password calculation vector checks the response key, LMv2 response and NT proof independently. Source: https://winprotocoldocs-bhdugrdyduf5h2e4.b02.azurefd.net/MS-NLMP/%5BMS-NLMP%5D-151016.pdf . Contemporary protocol definition: https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-nlmp/5e550938-91d4-459f-b67d-75d70009e3f3 .

Fixed acceptance: official vector; malformed/truncated/bad-offset/duplicate AV challenge rejection; old-version downgrade and MIC/EPA refusal; random challenge variability; real same-socket HTTP server independently checks the response; no authenticated replay on replacement connection, no redirect credential forwarding; TLS verification, total timeout and cancellation preserved; browser auth entry and packaged desktop flow. Imported/exported plaintext credential warnings remain. A development-only deterministic vector input is not exposed through application auth settings.

Research rejected @node-ntlm/core0.3.2 as a direct dependency because its inspected Type3 path uses Math.random and may fall back to v1. No code from that package or the original Apipost runtime is copied. Only a pinned standalone MD4 primitive is considered, with its license and dependency audit.
