# 私有 URL 查询编辑器状态

这是存储约定，不添加界面或任何发送行为。实际地址始终是接口定义的 `url`；下方结构化 `query` 和继承参数的含义不变。禁用的 URL 原始查询项留在项目的 Git 忽略文件中，不进入普通定义、cURL、OpenAPI、Apipost 定义、范围导出、脚本运行或 MCP 接口详情。之前实际启用过的查询内容仍可能存在于既有定义历史中，本功能不擦除历史。

项目完整本机备份（项目导出 `backup` 或既有 `native` 备份别名）会携带有效的私有编辑器状态。禁用项也可能包含凭据：只在可信位置保管完整备份，不要公开分享。只用 Git 克隆项目时，仅保留已保存的有效 URL，不带私有编辑器状态；要带回私有数据请使用完整备份和恢复流程。

私有文件和请求在同一项目事务恢复流程中写入；接口归属和已启用项必须与有效 URL 完全一致。普通保存未携带这一字段时，只保留仍绑定原有效 URL 的记录；外部替换已保存的接口文件，即使随后还原文本，也不会重新激活旧记录。此保护基于普通本机文件代际标识，不是针对能篡改项目文件和本地私有清单的使用者的安全边界。备份恢复使用新项目身份并重新绑定其私有状态。

如果已登记的私有文件丢失或无效，所有者仍可以读取、使用并保存规范接口定义。服务端仅报告固定的缺失／无效状态，不提供文件名、解析细节或字段值。普通配置和活动记录的事务会保留登记和原私有文件，不会删除、改写或重建它；修复前拒绝修改禁用项及生成声称完整的备份。Git 定义与普通范围、OpenAPI 和 Apipost 定义导出不受影响，也不包含该状态。可从可信的同一项目副本恢复私有文件并重新加载；只有与当前接口文件身份和有效地址相符的禁用项才会恢复。已有健康完整备份仍可恢复为独立项目。
