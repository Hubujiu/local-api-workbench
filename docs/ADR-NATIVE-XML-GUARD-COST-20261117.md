# 保留完整 XML 防篡改检查，减少描述符比较成本

## 实际失败与定位

整合 PR #264 的第三轮 [CI 44116790576](https://github.com/Hubujiu/local-api-workbench/actions/runs/44116790576) 在 macOS shard 5 的 `native-comparator-assertion-workflow.test.mjs` 失败。正文仅 41 字节，同一阶段有七个 XML 断言；兼容层活动时间约 85ms、用户脚本约 171ms，超过共享 250ms 活动预算。Worker 总墙钟约 571ms，未触及 2s 总期限。原生证据转换和输出序列化尚未执行，不能将其归因为此前补齐的证据计费。

独立的 fresh QuickJS 分段观测显示，七次 XML 任务中，完整内建对象检查累计 33.1–39.2ms，占该小正文 XML 执行时间约 78%；七次 DOM 解析仅 1.9–2.5ms。防篡改检查不能省略，但旧描述符比较对六种字段逐一执行双方 `hasOwn`，每个描述符重复十二次存在性检查。

## 修改及保持的合同

使用捕获的原生 `Object.getOwnPropertyDescriptor` 所保证的描述符形状：

- `enumerable`、`configurable` 总是自有布尔字段。
- 数据描述符具有自有 `value`、`writable`；访问器描述符具有自有 `get`、`set`。
- 先用捕获的 `hasOwn` 比较双方是否为数据描述符，再读取该形状的自有字段。
- 值、getter、setter 仍使用捕获的 `Object.is` 比较，保留 `NaN` 和正负零语义。
- 缺失描述符、全局绑定、全部对象键、键顺序、符号属性、函数与原型链仍逐任务完整检查。

没有读取不存在的字段，因此原型上注入的 getter 不会参与比较。没有缓存 DOM 或检查结果，没有减少检查对象、XML 断言或 XPath 查询，没有移动实际工作到预算之外。64KiB/32 层/2000 节点的 XML 边界、250ms 共享活动预算和 2s 总期限保持不变。生成的 XML bundle 及来源摘要已同步重建，并通过可复现构建检查。

## 验证证据与解释范围

在同一进程中交替测量原始和形状特化的生产等价函数，每种十个样本，完整原始记录保留。去掉双方首个预热样本后，各九个样本的七次完整检查墙钟中位数从 27.20ms 降至 11.76ms；CPU 中位数从 28.03ms 降至 12.50ms。这是相同检查工作的成本比较，不是对 CI 宿主实时性的保证。

带分段观测的完整 XML 三个固定样本，旧版用户工作为 41.9–51.0ms，新版为 22.6–52.1ms；新版首个冷样本仍较慢。保留全部样本，不把较低的两个样本外推成稳定的端到端加速比，也不声称重现了历史 runner 的具体停顿。

实际 tracked QuickJS 的 30 种篡改/等价场景直接读取生产实现，旧版与新版 A/B 共 60/60 符合预期，所有 getter/setter 调用次数均为零。场景覆盖描述符种类切换、三种标志、值和访问器身份、`NaN`/正负零、全局增删、符号/嵌套函数/迭代器/原型/键顺序，以及快照前后的全部六种继承字段污染。正式回归加入既有 XML 边界文件，没有新增 core 文件或改变分片数量。

十个相关测试文件共 **94/94 通过，0 失败、取消或跳过**，覆盖 XML 安全边界、真实 HTTP/SDK/CLI 工作流、当前正文变化、共享活动预算和此前的诊断计费故障注入。完整三平台结果仍须以新提交自身的 CI 为准。

## 同轮另一处失败的边界

第三轮最终为 44 个成功作业、3 个失败作业：上述 XML 分片、macOS shard 7 和正确拒绝的 `required`。shard 7 的嵌套 HTTP/gRPC 流程在一个 HTTP 前置阶段失败；其自定义函数列表为空，但仍执行真实的 `const utils=Object.create(null);` 初始化。该同步段墙钟约 246ms、CPU 约 5.054ms，加上约 28ms 兼容层工作后耗尽活动预算；其余十五个步骤，包括全部 gRPC 步骤均通过。

现有日志不能确定这段同步求值中的具体调度停顿、原生等待或 VM 内部延迟。它不使用 XML guard，不能宣称本优化修复了该失败，也没有将初始化移出计费、扩大预算或单独重跑该作业。历史失败继续保留，整合是否通过由修订后的完整 CI 决定。
