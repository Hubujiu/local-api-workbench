# Bounded staged load of saved HTTP plans

This is a backend-only, constrained staged-load contract. It reuses `runPlan`, the existing request transport, script sandbox, frozen plan and per-iteration variable/cookie isolation. It does not attempt to run the original application's worker, copy its code, or claim its native event format is completely understood. The original static implementation's intermediate ramp-up starts omit the initial hold offset; this contract instead makes all stage offsets cumulative.

`POST /api/projects/:id/staged-load` accepts `planId`, optional `environmentId` and `runId`, and `schedule` with `initialVUs`, `stages: [{durationSeconds, targetVUs}]`, and `maxIterations`. The plan must be a saved, linear HTTP plan with 1–10 enabled steps, no collection scope or redirect, and no native writes. Conditional/repeat/protocol steps and disabled steps are explicitly unsupported by this initial contract. The snapshot is at most 1 MiB. Initial/target VUs range from 0–10, each of 1–10 stage durations is a positive whole second, total duration is at most 60 seconds, and `steps × maxIterations` is at most 100. A ramp changes VUs in integer increments at equally spaced offsets; downscaling lets an already-started iteration finish and does not admit another for that slot. The total deadline interrupts remaining work. Iteration limit stops admission but does not remove the total deadline. A ramp from zero reaching its first VU exactly at the final deadline may perform no iterations.

An SSE response emits `start`, zero or more `report`, `reportEnd`, and `complete`. Reports contain only counters, step IDs, response-byte totals, and duration percentiles; they do not include URLs, bodies, headers, variables or remote errors. Per-step timings are HTTP response-duration samples in milliseconds, and P50/P90/P95/P99 use the nearest-rank method; `timingSamples` discloses how many responses had a duration. Rate fields are cumulative completed steps or iterations divided by elapsed time, not the original product's QPS or interval throughput. Values are bounded by the admission limits, so exact sorting is used instead of a histogram. Stop reasons distinguish `iteration-limit`, `duration`, `cancelled`, and `observer-failed`. The report is transient and is not saved as project history.

Explicit `/api/cancel` keeps a connected SSE caller and emits a cancelled terminal report; a disconnected caller aborts in-flight work and emits nothing further. Cancellation cannot undo a request already delivered to a remote system. Native database access is not enabled for this execution entrypoint; unsupported operations fail through the existing runner without being granted new capabilities. This endpoint can send real requests only when the authenticated owner invokes it. Tests use loopback peers only.
