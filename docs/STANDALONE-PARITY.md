# Apipost 单机版功能对照与交付门槛

核对日期：2026-11-17。Workbench 对照版本：[#259](https://github.com/Hubujiu/local-api-workbench/pull/259) `19bd7cbd57c99804fb712430ea6f8ede498938b0`。本文是当前验收清单，不代表新版本已发行。[历史 98 项矩阵](PARITY-CURRENT.md)保留各项细节和历史证据，不能当作今天的验收结果。

## 范围和判定

- **单机明确**：以[产品页](https://offline.apipost.net/)、[单机帮助](https://offline.apipost.net/help/)、[MCP 2.0](https://offline.apipost.net/mcp/)和[AI 执行计划](https://offline.apipost.net/help/executions/)为准。
- **厂商通用、单机待核**：不能因为通用 wiki 有某一项就声称当前单机版逐项支持；继续查单机实样和版本，保留已承诺的 Workbench 功能。
- **明确排除**：购买、试用倒计时、付费解锁、订阅、设备绑定 License、强制账户/联网认证和云协同。不复制原厂代码或绕过原厂授权。Workbench 本体为 [MIT](../LICENSE)，核心运行不需要第三方 AI 账号；可选 Agent 是外部工具，不作为功能解锁条件。
- **有实现**不等于可交付：代码、自动化回归、真实服务/人机操作和精确发行包分别记账。替代实现须完成同一用户任务，不要求复制品牌、像素或产品缺陷。

## 完成规则

1. 固定一个最终集成 head/tree。把兼容、能力差异、实测环境和证据记录在同一版本；不能继承旧分支绿灯或将跳过算通过。
2. 按真实缺口优先：补齐数据库产品连接闭环；验证并实现必要的单机 2.0 格式/协议兼容；完成 Windows 启动、升级、卸载保留数据与重装，再按明确平台范围处理发行信任。
3. 在合成数据和本地 fixture 验完关键 GUI、CLI/MCP、错误/取消、重启、离线和可恢复流程。同一整包关联版本、摘要、安装/使用文档、源码许可证及第三方许可证材料。
4. 交付前显式列出任何仍无法验证或不等价的项目；保留安全限制，不把临时试用包或草稿分支称作完整交付。
