# 智能字段 Mock 与条件响应期望

官方补充文档明确这两项能力不同：
- https://wiki.apipost.cn/docs/project_set/mock_rule/ ：按字段名通配符和类型生成数据。
- https://wiki.apipost.cn/docs/http/mock/ ：按请求触发条件选择响应期望。

此前已实现的是条件响应选择。现在独立增加项目级字段规则，不能用前者代替后者算完成。

## 本工具明确契约
- 条件响应规则优先，其后是显式响应示例；没有示例且有 2xx JSON 响应 Schema 时才自动生成 Mock。
- Schema 的 const/example/default/enum 优先；字段 mock 表达式次之；项目自定义字段规则按顺序匹配，再到可选内置规则，最后采用类型样例。
- 支持 *、?、字符集/范围、取反字符集和有界花括号选项。规则可选择字段类型和忽略大小写。
- 使用固定 32 位种子，给定 Schema/规则/顺序生成可复现数据。内置头像为本地 data URI，URL/邮箱使用 example.test，IP 使用文档保留地址。
- 只解析列出的有界 Mock 函数或 JSON/文本常量，不 eval 任意代码，不提供完整 Mock.js 兼容声明。
- 每项目最多100规则、单模式200字符、32展开选项、自定义总模式复杂度20000 token、一次生成最多200万匹配步；沿用 Schema 生成节点/输出上限。
- 生成值检查基础类型与常见数值/长度约束；复杂 Schema 仍要求显式 example，不是通用验证器。
- 固定验收：五类通配符、顺序/类型/禁用/内置开关、种子复现、显式示例优先、真实 HTTP 自动 Mock 与 Body 样例一致、UI 配置保存并实际生成姓名字段。
