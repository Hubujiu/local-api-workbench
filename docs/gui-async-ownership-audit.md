# GUI async ownership audit

Baseline: 41ca841a836a099c00c7d3f49b69d2df9d078122 (#216). References below use baseline line numbers. Scope: every async/await site in public/app.js, registered callbacks, and asynchronous public helper modules excluding vendored code. Independent front/back passes traced shared save, navigation and execution. This inventory explicitly distinguishes fixes from residual risks.

## Common policy

Reuse the existing single project-write coordinator, rather than independent import/case/plan locks. Acquire admission before awaited draft saves. Unknown execution outcomes must not auto-replay; a safe explicit project read permits a deliberate new execution. Server revisions remain authoritative. Read-only previews and global session polling need separate latest-wins tokens, not persistent-project locks.

Executed red tests selected this work: plan readback changed an edited name from new draft to old while dirty stayed true; double single-case clicks during a pending real save produced one PUT plus two execute POSTs, potentially duplicating irreversible external effects.

## Helper modules

- case-batch.js: bounded deep snapshot, sequential execution, cancellation/error stop; caller owns admission.
- step-editor.js: per-file generation; detached old state is not current collected edit.
- form-file-selection.js: WeakMap token, isCurrent and size checks after read.
- apipost-directory-input.js: stop checks before/after every read and bounded paths/bytes.
- mcp-settings-view.js: reveal/copy sequence and connected-root checks.
- variable-write-receipt.js: verifies revisions/before-values before selective adoption; retained for direct/batch requests.
- native-request-lifecycle.js and project-import-guard.js: existing pending/generation/unknown-outcome machinery reused for plans and execution, not independent locks.

## Remaining acceptance boundary

Residual preview-to-wrong-project writes, optimistic rollback, OAuth2 ownership and session generation remain prioritized follow-ups. This audit is not a blanket safety claim. Signed installers, real external database breadth and complete third-party migration compatibility are independent acceptance tracks.

## Preview ownership follow-up (based on #226)

The historical baseline findings above remain evidence, not a claim about later fixes. The dictionary-preview and bulk-error-code paths now capture the opening project object, edit version and modal revision. Both recheck before and after their read-only preview; changes to input, dismissal, a new modal, project replacement or edits invalidate the result. Dictionary confirmation advances synchronously to a new owned modal and rechecks before mutation. Both writes use the existing save coordinator; definite no-commit rollback uses the shared owner/version receipt and unknown outcomes retain the draft without automatic retry. This is not a global solution for every residual async path in the table.

The regression uses actual extracted app callbacks for both paths, including project switch, edits, dismissal, reopening, changed input, malformed results, confirmation ownership, success, definite rejection and unknown outcomes. These callback tests are not browser evidence; real-browser and complete CI results must be checked on the exact candidate head separately.
