# 有界脚本阶段执行基础

这是项目/精确目录共享脚本的内部执行基础；界面、继承规则和计划隔离另见 ADR-SHARED-SCRIPTS。

简单拼接源码或只await外层函数不足以保证前一作用域的HTTP回调和定时器已经完成。新的runScriptSequence逐阶段等待runScript的异步任务及线程退出，再把变量作用域、请求内局部变量和请求修改传给下一阶段；不通过Node对象向沙箱传权限。

## 固定契约

- 每阶段独立QuickJS上下文；只通过明确的apt/pm变量与请求状态共享，不共享词法声明。阶段名附在断言/子请求证据与日志中。
- 最多4阶段，源码合计100000字符。一个原有前置或后置阶段的所有子阶段共享250ms活动预算、2秒墙钟截止、10次HTTP、100次定时器、1000次Faker、10000个微任务、1000条断言、100条日志及1MiB UTF-8输出上限。并行HTTP最多4、活动定时器最多32，VM仍为16MiB。
- 子阶段只拿剩余预算，绝不因新VM重置配额。runScript内部参数只能降低既有上限；完成后返回的活动时间/计数由worker在VM外采集，脚本不能伪造。
- 失败断言终止后续阶段且保留结果；异常带阶段来源和既有网络证据。取消/错误仍等工作线程退出；网络权限与Cookie session只沿用调用者已有授权。
- 单个原有脚本入口的默认预算不变。尚未改变计划执行规则；计划仍只运行显式脚本，不因未来共享设置而隐式加入代码。

固定验收覆盖HTTP回调完成后跨阶段变量/局部值/请求传播、失败停止、活动/墙钟总预算、累计网络/定时器/Faker/断言/日志限制、降低微任务预算及拒绝扩大上限。所有原脚本回归继续运行。

## Faker 配额验收与耗时分离

组合提交 a1c46e7 的 Windows job [121689038749](https://github.com/Hubujiu/local-api-workbench/actions/runs/40356149275/job/121689038749) 中，六个固定配额样本的第二个先耗尽活动预算，并非成功越过 Faker 配额：第一阶段600次用了184ms（兼容层71ms、用户阶段114ms，其中冷加载Faker57ms），第二阶段仅余66ms，107次调用时超时。兼容层CPU仅16ms，不能把全部墙钟耗时归因于解析器，也不宣称本地优化解决了Windows调度停顿。

1000次累计配额验收仍运行六个独立600+600样本、调用真实Faker提供方，且仍只接受原配额错误；改为已存在的 `builtinVariable` 入口，省去反复解析相同 `replaceIn` 模板。两条入口最终调用同一宿主闭包计数器，没有新测试钩子、预热、缓存生成值或预算例外。额外断言第一阶段600次、第二阶段第401次拒绝，下一阶段活动预算精确等于250ms减已用时间。

真实 `replaceIn` 的模板/作用域/UTF-8上限验收不移除，并新增两个固定方向的直接调用与插值混合阶段验收：在显式降低至3次的配额下2+1成功、2+2在第二阶段第2次拒绝。这样分别验证真实插值入口共用计数器和原1000次绝对上限，不能把时间错误当配额成功。250ms活动预算、2秒墙钟、六个样本及全部原配额不变。独立本地六对冷worker探针的用户阶段中位耗时从35.5/32.5ms降到26/22.5ms；只是当前环境观测，不是跨平台性能保证，精确提交Windows CI仍须验证。

本次相关3文件21项通过。在自建 `/tmp` 隔离副本中，仅故意把阶段结束后的Faker剩余额度扣减替换成每阶段重置：原1000次累计用例和新增混合入口用例均以 `Missing expected rejection` 真正失败。该反例未修改工作树生产文件，确认验收不是只验证一个错误字符串或被独立计数器自证。
