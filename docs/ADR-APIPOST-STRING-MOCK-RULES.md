# Explicit-pool original string Mock rules

Static inspection of the official offline 2.0.0 embedded mockjs5-pro extension shows that its string generator uses lodash sampleSize on an explicit pool. This differs from the Local API native string generator: source positions are sampled without replacement, requested lengths greater than the pool length are clipped, and repeated characters already in the pool remain repeated positions.

Modern JSON and the supported original-directory JSON subset can import string-typed rules with @string("pool",length) or @string("pool",min,max). Arguments must be JSON literals. Pools contain 1–64 ASCII letters, digits, spaces, underscores, dots or hyphens; lengths are integers from 0 to 64 with min no greater than max. This deliberately excludes nested @ expressions, executable arguments, coercive numeric-pool overloads, single-quoted/non-JSON arguments, Unicode pools and unverified overloads. No vendor code or expression executes during import.

Matching uses the same bounded original exact/wildcard mode and strict field types as the numeric import subset. Source identities survive storage and editor changes. Schema examples/defaults/enums retain existing priority; generated text must satisfy existing output validation, including length constraints, or fail explicitly. Numeric minimum/maximum bypass does not apply to string rules. Existing Local API string generators keep their original behavior. Seeded sampling is illustrative and does not claim the vendor's random sequence or distribution.

Independent tests cover permutations, repeated positions, clipped/zero/ranged lengths, strict type matching, atomic refusal, actual sample/Mock HTTP and browser edit/reload/source preservation. This is not full Mock.js/Faker support or original GUI parity.

String-typed rules may also use @pick(["candidate",...]) with exactly one JSON array argument, 1–64 well-formed Unicode strings, at most 256 UTF-8 bytes each and at most 4 KiB for the expression. Source inspection shows the one-array/no-count overload returns one literal candidate. Entries containing @ are rejected because the original placeholder parser may recursively interpret parameter arrays containing placeholders. Arrays/objects/numbers as candidates, empty lists and extra count arguments are unsupported. Literal braces are not interpolated. This path preserves complete Unicode strings as candidate values without relying on character segmentation.

Character rules accept @character("pool") and @char("pool") with one explicit 1–64 printable ASCII string. The original named pools lower/upper/number/alpha/symbol/undefined are resolved case-insensitively; other accepted strings are literal pools. Exactly one character is selected per call. Inputs containing @, prototype-like alias names, Unicode/control characters, empty/implicit pools or extra arguments are rejected. The symbol alias may produce @ as literal output; output is not recursively evaluated. Static inspection also verified these base generator names are not overridden by the bundled extension registrations.

Word rules accept @word, @word(), @word(length) and @word(min,max). The inspected source range helper defaults to 3–10 lowercase ASCII letters; one argument fixes the length and two select an inclusive range. Explicit lengths are bounded to integers from 0 to 64. This generator creates letter strings, not dictionary words. Fractional/negative lengths, reversed ranges, coercive string arguments and extra arguments are rejected; Local API word rules retain their existing semantics.

English title/sentence/paragraph composition follows the inspected source methods and range helper. Bare or empty calls default to 3–7 title words, 12–18 sentence words, or 3–7 paragraph sentences; fixed and ranged integer counts are accepted up to 32 words or 8 sentences. Each word contains 3–10 lowercase letters, titles capitalize every word, sentences capitalize the first word and append a period, and paragraphs join default sentences with spaces. Zero title/paragraph counts yield empty strings; zero sentence words still yield a period. Outputs are bounded to 2 KiB, and unsupported/coercive counts fail. These are illustrative letter-based texts, not natural-language generation.

The effective bundled guid and uuid names both resolve to UUIDv4 generators: the Faker registration overrides base guid, and the later extension overrides uuid. Reading only the shadowed base guid implementation would incorrectly imply mixed-case, non-versioned identifiers and pool sampling. The supported no-argument forms @guid/@guid()/@uuid/@uuid() emit lowercase UUIDv4-shaped fixture strings with the required version and variant bits, using the existing seeded generator. Arguments are rejected rather than ignored. These are deterministic Mock data, not cryptographically secure identifiers or a reproduction of the vendor random stream.

The effective string override also supports bounded no-count calls: @string and @string() select one character from the default uppercase/lowercase/digit pool; @string("pool") selects one character from the accepted explicit ASCII pool. In particular "lower" is literal pool text here, not the character generator alias. This is not the shadowed base Mock.js default-length behavior. Empty/Unicode pools, nested placeholders, numeric/coercive overloads and invalid arguments remain rejected. Actual Mock HTTP covers a deterministic single-character pool.
