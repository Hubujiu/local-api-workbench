# 项目与目录共享认证

官方功能依据：https://wiki.apipost.cn/docs/http/global-paras/ 及 https://wiki.apipost.cn/docs/folder/setting 。独立实现明确以下继承和安全边界。

- 同一公共参数设置页按整个项目/精确目录选择作用范围。勾选“设置认证覆盖”后配置已有支持的认证类型；不勾选时目录继承项目、项目不添加认证。目录勾选并选none表示明确阻止项目认证。
- 接口具体认证（非none）优先于目录/项目配置。接口认证为none时可继承；取消“继承认证”则不添加共享认证。认证继承开关与参数继承开关独立，避免无意把禁用参数等同禁用认证。
- 只匹配当前完整目录名，不递归。目录重命名转移认证，删除移除，目标配置冲突先拒绝再修改，保持旧快照独立。
- 新计划/用例创建时冻结认证类型和模板；环境变量执行时解析。旧计划/用例标记为已冻结，升级后不自动获得项目凭据。单次调试、压测、授权MCP及cURL使用当前配置。
- 所有认证仍使用原执行器规则：TLS验证不关闭，NTLM不降级/重放、不读取系统密钥、OAuth不自动申请令牌。共享编辑器只能填写已有令牌，不自动跳转授权页。
- 共享凭据可能发送给作用范围内多个目标站点，界面明确提醒；保存、导出、历史和快照可能含明文。用户应使用变量、HTTPS并检查目的地址；系统不自动填入任何真实凭据。
- 每作用域最多64KiB，最多100个目录、目录认证总计256KiB，字段仅允许文本/数字/布尔，拒绝未知认证类型、嵌套字段和原型特殊名称。

固定验收覆盖优先级、显式none、关闭继承、兄弟/后代隔离、旧快照不漂移、重命名/删除不改源数据、真实HTTP及cURL签头、浏览器掩码编辑/保存/继承发送/关闭继承。共享前后置JavaScript另见ADR-SHARED-SCRIPTS。
