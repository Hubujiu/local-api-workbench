# Bounded original date/time Mock generators

The inspected offline 2.0.0 Mockjs date/time/datetime implementation samples a timestamp between epoch zero and the current clock, then formats it with system-local Date getters. It does not use the Local API native generator's fixed 2020s interval. Imported string rules preserve that separate behavior; existing Local API date rules are unchanged.

Bare or empty date/time/datetime calls use yyyy-MM-dd, HH:mm:ss and yyyy-MM-dd HH:mm:ss defaults. One explicit JSON format string is allowed, up to 64 characters. Supported tokens are yyyy, yy/y, MM/M, dd/d, HH/H, hh/h, mm/m, ss/s, SS/S, A/a and T, with numeric or separator literals. The original y is a two-digit year alias; hh/h uses hours modulo 12, including zero at midnight and noon. SS pads milliseconds to three digits while S is unpadded. A/a emits AM/PM or am/pm. T is the epoch-millisecond timestamp, not an ISO separator. Unsupported/ambiguous runs (including YYYY and SSS), weekday/month names, timezone markers and executable or extra parameters fail explicitly. These meanings come from the statically inspected original token table, not Moment conventions.

A finite nonnegative TimeClip-safe clock and a bounded random fraction are required. Randomness remains seeded illustrative sampling, not a claim of vendor sequence/distribution equivalence. Date output also depends on the current clock and system timezone: a fixed seed alone does not freeze time. The settings label and imported-rule explanation disclose this. Tests can supply a private clock callback; no project setting, API credential or system timezone is changed by that hook.

Validation covers epoch/current-clock bounds, numeric formatting, unsupported input refusal, independent UTC/Shanghai/Kolkata/New York vectors including DST, unchanged native Local API generation, actual Mock HTTP/storage and browser editing with retained source identity. These checks do not execute the original application or establish complete native directory/UI parity.

The bounded now generator uses the current clock without consuming random samples. It supports no arguments, one exact lowercase truncation unit or one numeric format, or an explicit unit/format pair. Units are year/month/week/day/hour/minute/second (case-insensitive only in the explicit pair); unknown or ambiguous unit strings are rejected. Truncation follows local Date setter ordering, and weeks begin on Sunday, not ISO Monday. Default formatting is yyyy-MM-dd HH:mm:ss. Tests include year rollover, Sunday boundaries, four timezone vectors, actual Mock HTTP and preservation of other seeded generators.

The bundled Faker registration exposes isoTimestamp as the current Date.toISOString() value. Its bare and empty-call forms are supported without arguments. Unlike date/datetime it does not sample a random instant, and unlike now formatting it always emits UTC with milliseconds. The shared clock validation still applies; no random sample is consumed. Fixed vectors in four timezones and actual imported-rule Mock HTTP bound the generated instant to the request interval.
